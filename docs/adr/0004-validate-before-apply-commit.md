# ADR-0004: Валидация конфига до применения и до публичного коммита

Статус: Принят
Дата: 2026-11-11

## Контекст

При реализации Фазы 1 несколько раз гипотеза принималась за факт:

- несуществующая директива tftp-max-blocksize уронила dnsmasq --test
  (bad option at line 76);
- угаданный путь /etc/httpd2/httpd.conf не существовал на этой сборке;
- предполагаемая раскладка ISO (syslinux/vmlinuz, syslinux/full.cz) не
  совпала с реальной (в syslinux/ только isolinux.cfg).

Каждый случай — потенциальное падение живой службы или ложный коммит в
публичный репозиторий.

## Решение

Перед рестартом любой службы и перед публичным коммитом конфига
обязателен native-валидатор этого же компонента:

- dnsmasq --test
- /usr/sbin/httpd2 -t (или фактический бинарник Apache из ADR-0005)
- nft -c -f /etc/nftables/nftables.nft
- bash -n скрипт
- sshd -t при правках SSH

Если конфиг коммитится до end-to-end теста, он маркируется как
«валидирован, но не протестирован живьём»; тег фазы не ставится. Каждый
инцидент, вызванный угаданным путём, именем пакета/службы или директивой,
фиксируется в docs/troubleshooting.md.

## Последствия

Положительные:

- меньше поломок живых служб;
- честная история Git (коммитим факт, а не надежду);
- сильный портфолио-сигнал: проект инженерный, а не скопированный.

Отрицательные:

- workflow чуть медленнее.

Митигация:

- scripts/phase1_preflight.sh автоматизирует рутинную валидацию;
- правило «шаг не зелёный — дальше не идём» держится как ритуал.
