# ADR-0000: Контекст ТЗ, фазовая поставка и ADR-процесс

Статус: Принят
Дата: 2026-10-25

## Контекст

Проект реализует техническое задание ГК «Росатом» (направление: инфраструктурная
автоматизация и DevOps-практики) на отечественной ОС ALT Linux p10. ТЗ задаёт
целевую архитектуру и стек (провижининг, идентификация, периметр, DevOps-контур,
IaC/GitOps, hardening/DR), но не диктует каждый инженерный выбор; доступность
пакетов в ветке p10 ограничивает реализацию и требует обоснованных отклонений.

## Решение

Поставка разбивается на шесть фаз (перечень и критерии приёмки — в README
«Стек и статус фаз»; детальный план — docs/roadmap.md, создаётся следующим разом).
Каждое нетривиальное решение и каждое отклонение от буквального ТЗ фиксируется
как ADR в docs/adr/ по шаблону «Контекст → Решение → Последствия», статус
«Принят», имена файлов NNNN-kebab-case. Состояние инфраструктуры живёт в Git
(configs/, provisioning/, scripts/, ansible/); секреты в репозиторий не попадают.
Язык документации — русский под аудиторию ТЗ; literal-имена служб, путей и
директив не переводятся, чтобы код читался без кальки.

## Последствия

Положительные: аудзируемость, воспроизводимость, управление отклонениями через
обоснование, а не молча; единый голос проекта.
Отрицательные: оверхед на документирование.
Митигация: шаблоны ADR, предварительная проверка (scripts/phase1_preflight.sh),
правило ADR-0004 (валидировать до коммита) и ADR-0005 (факты из системы).
