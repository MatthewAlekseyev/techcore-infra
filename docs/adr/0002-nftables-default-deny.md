# ADR-0002: nftables default-deny, провижининг-хост не роутит

Статус: Принят
Дата: 2026-10-28

## Контекст

Лаба доступна из NAT-сегмента (enp0s3) для обновлений, но PXE-сегмент
(enp0s8) должен быть закрыт. Кроме того, lab-prov-01 не должен быть
роутером между сегментами: иначе internal-машины получат выход в интернет
мимо контроля, и рекламировать .10 как шлюз было бы ложью о топологии.

## Решение

nftables в режиме default-deny:

- policy drop на input и forward;
- явные allow на enp0s8 только для портов провижининга: udp 67, 68, 69
  (DHCP + TFTP) и tcp 80, 443 (HTTP kickstart и RPM);
- forward: policy drop — lab-prov-01 не маршрутизирует между сегментами.

Следствие для DHCP: опцию 3 (router) на .10 не выдаём, потому что .10 не
роутит. Шлюз появится только в Фазе 3 на lab-gw-01.

## Последствия

Положительные:

- минимальная атака-поверхность, видимая из одного файла;
- честная топология: конфиг не врёт про шлюз.

Отрицательные:

- мина TFTP: сервер отвечает данными с плавающих эфемерных портов, и
  stateful-фаервол без парсера дропает первый же DATA-блок;
- любой новый порт провижининга требует явного правила (иначе молча
  режется).

Митигация:

- загрузка и закрепление nf_conntrack_tftp (прозрачная линия защиты);
- явный диапазон tftp-portrange + правило nft как вторая линия (belt-and-
  suspenders на время Фазы 1, переход на одну явную линию в Фазе 6);
- после ADR-0003 порт cobbler 25151 мёртв и удаляется из правил.
